# Story 8.1.1: Endpoint Básico de Listagem de Clientes

Status: **done**

## Story

Como admin, quero acessar uma lista básica de todos os clientes cadastrados, para ter uma visão geral da minha base de clientes.

## Acceptance Criteria

1. [x] O endpoint GET /admin/customers deve retornar todos os clientes
2. [x] Os campos mínimos obrigatórios são: id, name, email, phone
3. [x] A resposta deve incluir paginação padrão (page=1, size=50)
4. [x] Deve ser possível ordenar por nome (ascendente e descendente)
5. [x] A API deve retornar status 200 OK em sucesso
6. [x] Deve haver tratamento de erros para casos de falha
7. [x] O endpoint deve ser protegido e exigir autenticação de admin
8. [x] Deve haver limitação de taxa para evitar abusos

## Tasks / Subtasks

- [x] Backend: Implementar endpoint GET /admin/customers
  - [x] Criar CustomerAdminController com método getAllCustomers
  - [x] Implementar lógica de paginação: Pageable com page e size
  - [x] Configurar ordenação por nome (asc/desc)
  - [x] Validar que usuário é admin via @PreAuthorize
  - [x] Adicionar rate limiting com @RateLimiter
  - [x] Implementar tratamento de exceções
- [x] Backend: Configurar modelo de resposta
  - [x] Criar DTO CustomerListResponse com campos obrigatórios
  - [x] Implementar conversão de Entity para DTO
  - [x] Adicionar metadados de paginação (totalElements, totalPages)
  - [x] Configurar serialização JSON adequada
- [x] Backend: Implementar repository queries
  - [x] Criar query findAllWithPagination no CustomerRepository
  - [x] Adicionar ordenação dinâmica por nome
  - [x] Implementar busca por status de cliente (ativo/inativo)
  - [x] Otimizar query com índices existentes
- [x] Testes: Implementar testes unitários
  - [x] Testar endpoint sem autenticação (deve retornar 401)
  - [x] Testar endpoint com usuário não admin (deve retornar 403)
  - [x] Testar paginação com diferentes parâmetros
  - [x] Testar ordenação ascendente e descendente
  - [x] Testar tratamento de exceções
