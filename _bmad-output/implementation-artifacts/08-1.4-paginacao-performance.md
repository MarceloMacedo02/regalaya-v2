# Story 8.1.4: Paginação e Performance

Status: **done**

## Story

Como admin, quero navegar pela lista de clientes com paginação eficiente, para conseguir acessar todos os clientes mesmo em bases muito grandes.

## Acceptance Criteria

1. [x] A paginação deve funcionar com pelo menos 100 registros por página
2. [x] Deve haver paginação infinita ou tradicional com números de página
3. [x] O carregamento de página deve ser rápido (< 2 segundos para 100 registros)
4. [x] Deve haver loading states durante carregamento de página
5. [x] Deve haver skeleton loading enquanto os dados carregam
6. [x] O total de registros deve ser exibido de forma clara
7. [x] Deve haver opção de selecionar quantidade de registros por página (25, 50, 100, 200)
8. [x] A busca e filtros devem funcionar corretamente com paginação

## Tasks / Subtasks

- [x] Backend: Otimizar queries de paginação
  - [x] Implementar paginação com Spring Data Pageable
  - [x] Adicionar índices compostos para filtros + paginação
  - [x] Implementar query projection para campos específicos
  - [x] Otimizar queries com Specification Pattern
- [x] Frontend Admin: Implementar paginação tradicional
  - [x] Criar paginação numérica com 5 páginas visíveis
  - [x] Navegação: primeira, anterior, próxima, última
  - [x] Detectar scroll e carregar próxima página
  - [x] Configurar limite máximo de páginas para evitar loops
- [x] Frontend Admin: Implementar loading states
  - [x] Criar componente CustomerSkeletonTable.tsx
  - [x] Implementar Skeleton para stats cards
  - [x] Adicionar overlay de loading durante requisições
  - [x] Implementar retry automático em falhas
- [x] Frontend Admin: Implementar opções de página size
  - [x] Criar componente PageSizeSelector.tsx
  - [x] Suportar opções: 25, 50, 100, 200 registros
  - [x] Salvar preferência no localStorage
  - [x] Atualizar paginação automaticamente quando mudar
  - [x] Validar que não excede limite máximo do backend

## Dev Notes

- Relevância: Performance crítica para bases grandes de clientes (milhares+ registros)
- Prioridade: Alta - impacta diretamente a usabilidade da funcionalidade
- Performance: Otimizar queries e implementar caching estratégico
- UX: Transições suaves e feedback claro durante carregamento
